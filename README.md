# 🤗 토닥토닥 건강일기

식단 기록을 통해 건강을 관리하는 웹 앱입니다.
**모든 데이터는 사용자의 브라우저(기기)에만 저장**되며 서버로 전송되지 않습니다. 로그인도 필요 없습니다.

## 실행 방법

필요한 것: **Node.js 18 이상** (https://nodejs.org 에서 LTS 버전 설치)

프로젝트 폴더에서 터미널(명령 프롬프트)을 열고:

```bash
npm install
```

개발 서버 실행:

```bash
npm run dev
```

터미널에 표시되는 주소(보통 http://localhost:5173, 사용 중이면 다른 포트)로 접속합니다.
PC·모바일 모두 사용 가능합니다.

배포용 정적 파일 만들기:

```bash
npm run build
```

`dist/` 폴더가 만들어집니다. 이 폴더를 그대로 정적 호스팅(Netlify·Vercel·GitHub Pages 등)에
올리면 됩니다. 라우팅은 `HashRouter`를 쓰므로 서버 리라이트 설정 없이도 동작하고,
`file://`로 열어도 화면이 나옵니다.

## 동작 방식

- **목표 칼로리 자동 계산** — Mifflin-St Jeor 공식으로 기초대사량(BMR)을 구하고, 활동량 계수를 곱해 활동대사량(TDEE)을 산출한 뒤 목표(감량 −500 / 유지 / 증량 +300 kcal)를 반영합니다. 안전을 위해 최소 1200kcal 이상으로 제한합니다.
- **음식 데이터** — 공통 한식 위주 109종을 앱에 내장해 인터넷 없이도 동작합니다. 목록에 없는 음식은 직접 등록할 수 있습니다. 기본 목록은 «없는 것만 골라 추가»하는 방식으로 동기화되므로, 앱을 업데이트해 기본 음식이 늘어나면 이미 쓰던 기기에도 자동으로 들어옵니다.
- **식단 추천** — 서버나 AI 없이 동작하는 규칙 기반 엔진입니다. 남은 칼로리 적합도, 단백질 밀도, 카테고리 다양성을 점수화해 조합을 제안합니다.
- **운동 추천·소모 칼로리** — 운동 29종에 MET(대사당량) 값을 붙여 `kcal/분 = MET × 3.5 × 체중 ÷ 200` 공식으로 계산합니다. 체중이 반영되므로 사람마다 결과가 다릅니다. 목표를 초과한 만큼(초과가 없으면 200kcal)을 태울 수 있는 운동과 필요 시간을 제안하고, 3분 미만·120분 초과처럼 비현실적인 것은 걸러 짧게 끝나는 순으로 보여줍니다. 운동을 기록하면 **순 섭취 = 섭취 − 소모**로 다시 계산되어 추천도 함께 갱신됩니다.
- **감량 목표 설정** — 목표 체중과 목표 날짜를 정하면 필요한 주간 감량 속도를 역산하고, 여기서 하루 칼로리 적자와 목표 칼로리를 계산합니다. 주 1kg을 넘으면 «빠듯함», 1.5kg을 넘으면 «무리»로 판정하고 주 0.5kg 기준의 현실적인 날짜를 제안합니다. 하루 섭취가 1200kcal 아래로 내려가지 않도록, 적자는 하루 1000kcal로 제한합니다. 목표가 정상 BMI(18.5) 미만이면 경고합니다.
- **감량 진행 추적** — 체중 기록의 최소제곱 회귀 기울기로 실제 주간 감량 속도를 구합니다(하루 단위 수분 변동에 덜 흔들립니다). 이 속도로 목표 도달 예상일을 계산하고, 설정한 목표일과 비교해 보여줍니다. 체지방 1kg ≈ 7700kcal 기준입니다.
- **수면 기록** — 취침·기상 시각을 넣으면 수면 시간을 계산합니다(23:30→07:00처럼 자정을 넘겨도 정상 계산). 성인 권장 7~9시간을 기준으로 부족·적정·과다를 판정하고, 최근 7일 추이와 수면의 질 분포를 보여줍니다. 하루 한 건만 저장되며 같은 날짜는 덮어씁니다.
- **복약 알림** — 브라우저 알림(Web Notification)을 사용합니다. **앱(탭)이 열려 있는 동안에만** 동작하며, 예정 시각부터 10분 안에 한 번 알립니다. 앱을 닫아도 오는 백그라운드 푸시는 서버가 필요해 지원하지 않습니다.
- **혈압 기록** — 수축기/이완기 값을 대한고혈압학회 기준 6단계(정상 · 주의혈압 · 고혈압전단계 · 1기 · 2기 · 위기)로 분류합니다(`src/lib/bp.ts`). 스마트워치 연동 버튼은 **동작을 흉내 낸 데모**입니다. 웹 앱은 애플워치·갤럭시워치의 측정값에 직접 접근할 수 없어, 실제 연동을 하려면 네이티브 앱과 서버가 필요합니다.
- **스트릭·뱃지·보상** — 기록을 남긴 날이 연속으로 이어지면 스트릭이 쌓이고, 조건을 만족하면 뱃지 12종을 얻습니다(`src/lib/streaks.ts`). 뱃지 개수에 따라 스스로에게 줄 보상 쿠폰(커피 3개, 디저트 6개, 치팅데이 10개, 특별보상 12개)을 사용 처리할 수 있습니다(`src/lib/rewards.ts`).
- **소리** — 오디오 파일 없이 **Web Audio API로 직접 합성**합니다(`src/lib/sound.ts`). 앱을 열면 인사 징글이, 버튼을 누르면 강아지 «멍!» 효과음이 납니다. 브라우저 자동재생 정책 때문에 첫 소리는 화면을 한 번 터치한 뒤부터 납니다. 설정 화면에서 끌 수 있고, 설정값은 `localStorage`에 저장됩니다.

## 데이터 보관 — 한 번 입력하면 다시 묻지 않기

기본 저장소는 IndexedDB이지만, 그것만으로는 기록이 사라질 수 있는 경우가 있어 `src/lib/persist.ts`에서 세 겹으로 막습니다.

| 위험 | 대비책 |
|------|--------|
| 브라우저가 저장 공간을 회수 (iOS 사파리는 7일간 안 쓰면 삭제) | 앱 시작 시 `navigator.storage.persist()`로 **영구 저장을 요청**. 설정 화면에서 상태를 보고 다시 요청할 수 있음 |
| IndexedDB를 못 쓰는 환경 (HTML을 `file://`로 직접 열기 등) | 프로필을 `localStorage`에도 **사본으로 보관**하고, IndexedDB가 비었거나 막혔으면 사본으로 되살림 |
| 저장 버튼을 누르기 전에 창을 닫음 | 온보딩 입력 폼을 **입력할 때마다 자동 임시저장**(`todak-draft-onboarding`), 정식 저장 시 삭제 |

- 프로필은 항상 **한 건만** 유지됩니다. `saveProfile()`은 읽기와 쓰기를 한 트랜잭션으로 묶어, 저장이 동시에 두 번 호출돼도 중복 행이 생기지 않고 과거에 중복된 행은 정리합니다.
- **설정 → 모든 데이터 초기화**는 IndexedDB뿐 아니라 위의 사본·임시저장본까지 지웁니다. 안 그러면 초기화해도 프로필이 되살아납니다.
- 기기가 다르면(PC ↔ 휴대폰) 저장소가 완전히 분리됩니다. 옮기려면 **설정 → 데이터 백업(JSON)** 으로 내려받아 다른 기기에서 **백업 불러오기** 하세요.
- 주소가 다르면(`localhost:5173` ↔ `localhost:5174`, http ↔ file) 브라우저가 다른 사이트로 보기 때문에 저장소도 갈립니다. 늘 같은 주소로 접속하세요.

## 한 파일로 배포하기

```bash
npm run standalone
```

`dist/standalone.html` 파일 하나가 만들어집니다. CSS·JS·폰트·이미지가 전부 안에 들어 있어
외부 요청이 0건이고, 서버 없이 더블클릭으로 열립니다. 출력 경로를 직접 정하려면
`node scripts/bundle-standalone.mjs "원하는/경로.html"` 처럼 인자를 주면 됩니다.

`src/components/WorkoutScene.tsx`는 홈트레이닝 장면 일러스트입니다(모바일 트레이너 화면 · 덤벨 · 복근 운동 자세).
`caption` 값으로 말풍선 문구를 바꿀 수 있고, 홈 화면과 추천 화면에서 씁니다.

`#/art` 경로로 접속하면 전체 카탈로그를 볼 수 있습니다.
심전도 라인·하트 등 배경 장식은 `src/components/Decor.tsx`에 있습니다.

## 소스 구조

```
├─ index.html                 진입 HTML
├─ scripts/                   빌드 결과를 HTML 한 파일로 합치는 스크립트
├─ vite.config.ts             빌드 설정 (에셋 인라인, 포트는 환경변수 PORT)
├─ tailwind.config.js         색상 팔레트·폰트 정의
├─ public/                    파비콘 등 정적 파일
└─ src/
   ├─ main.tsx                React 진입점 (HashRouter)
   ├─ App.tsx                 라우팅 + 하단 탭 바 8종 + 소리 초기화
   ├─ types.ts                전체 도메인 타입
   ├─ db/db.ts                Dexie(IndexedDB) 스키마 v7 + 음식 시드
   ├─ data/                   내장 데이터 — foods.ts(한식 109종), exercises.ts(운동 29종 MET)
   ├─ store/useProfile.ts     Zustand 전역 프로필 상태
   ├─ lib/                    순수 로직 (UI 없음, 여기만 봐도 계산식을 알 수 있음)
   │   ├─ nutrition.ts        BMR·TDEE·목표 칼로리·매크로
   │   ├─ weightLoss.ts       감량 계획·회귀 기반 실제 속도·도달 예상일
   │   ├─ exercise.ts         MET 소모 칼로리·운동 추천
   │   ├─ recommend.ts        규칙 기반 식단 추천 엔진
   │   ├─ meds.ts             복용 슬롯 생성·체크·다음 복용
   │   ├─ sleep.ts            수면 시간 계산(자정 넘김)·평가
   │   ├─ bp.ts               혈압 분류(대한고혈압학회 기준)
   │   ├─ streaks.ts          연속 기록·뱃지 12종
   │   ├─ rewards.ts          보상 쿠폰
   │   ├─ sound.ts            Web Audio 합성 (인사 징글·강아지 효과음)
   │   ├─ persist.ts          영구 저장 요청·프로필 사본·입력 임시저장
   │   ├─ image.ts            식단 사진 리사이즈·저장
   │   ├─ dates.ts            날짜 키·포맷 유틸
   │   ├─ emoji.ts            카테고리별 이모지 매핑
   │   └─ useMedReminder.ts   복약 알림 훅
   ├─ pages/                  화면 11종 (Dashboard·Diary·Meds·Sleep·Bp·Weight·Plan·Report·Settings·Onboarding·ArtGallery)
   ├─ components/             재사용 UI + 인라인 SVG 일러스트
   └─ assets/
       ├─ characters/         움직이는 캐릭터 SVG 8종 (SVG 안에 CSS 애니메이션 내장)
       └─ fonts/              Gamja Flower 웹폰트 (SIL OFL, OFL.txt 참고)
```

`npm install`이 만드는 `node_modules/`와 `npm run build`가 만드는 `dist/`는 소스가 아니므로
이 압축 파일에 들어 있지 않습니다. 위 명령으로 언제든 다시 만들 수 있습니다.

## 기술 스택

Vite 5 · React 18 · TypeScript 5 · Tailwind CSS 3 · Dexie 4(IndexedDB) · Zustand 4 · Recharts 2 · date-fns 3

외부 API·서버·계정을 전혀 쓰지 않습니다. 인터넷 없이도 전부 동작합니다.

## 주의사항

브라우저 데이터(사이트 데이터/쿠키)를 삭제하면 기록도 함께 사라집니다.
**설정 → 데이터 백업**으로 주기적으로 JSON 파일을 내려받아 두세요.

> 이 앱이 제공하는 칼로리·영양 정보는 일반적인 참고용 표준값입니다. 질환이 있거나 전문적인 식이 조절이 필요한 경우 의사·영양사와 상담하세요.
